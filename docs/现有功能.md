# 基础库现有功能

本文梳理 `Library` 基础包。它随公开基础库导出，是业务插件共同复用的策略执行层和发布工具箱，不是带菜单的应用插件。

## 模块边界

- 提供标准分层、认证鉴权、租户与数据范围、响应异常、日志脱敏和通用工具。
- 提供插件清单注册、源码期插件 ZIP 生命周期、数据库发布包和前端发布能力。
- 不定义具体业务角色、菜单、状态机或业务开放接口。

## 已落地能力

| 能力域 | 当前能力 |
| --- | --- |
| 标准分层 | `CoreController`、`CoreService`、`CoreMapper`、`CoreModel` 及标准 CRUD |
| 查询与写入 | 参数白名单、分页、搜索、排序、fillable 过滤、软删、恢复、硬删和状态动作 |
| 登录会话 | JWT 签发、校验、刷新、注销、黑名单和登录主体接口 |
| 权限范围 | `#[Auth]`、路由门禁、超级管理员、租户隔离和部门/本人数据范围 |
| 响应异常 | 统一业务响应、未认证、无权限、业务异常和路由 404 处理 |
| 中间件 | CORS、演示写保护、语言、请求日志、静态站点和路由鉴权 |
| 审计安全 | `#[Logger]`、模型变更、请求 ID、异常格式、敏感字段过滤和长度限制 |
| 插件注册 | `plugin.json`、菜单种子、模块能力、前端、语言包和迁移目录注册 |
| 插件管理 | 源码期打包、安装、移除、备份和恢复 ZIP，并维护 Composer path 接入 |
| 发布数据库 | 运行备份/恢复、v2 双 schema 安装包、必要/全量数据、dry-run 和哈希校验 |
| 前端发布 | 从 Phar 中展开已构建前端归档并保留动态运行配置 |
| 文档与模型工具 | 文档覆盖检查、模型字段索引和数据库结构索引构建 |
| OpenAPI 工具 | 可供业务插件复用的签名、nonce、时间窗和访问令牌组件 |

## 关键流程

### HTTP 与数据访问

请求经过中间件、登录与权限检查后进入 Controller、Service 和 Mapper；`TenantContext` 先确定租户，CoreModel 和 CoreMapper 再应用租户范围与数据范围，最终由统一异常处理器返回标准响应并记录日志。

### 源码期插件生命周期

插件经 `package` 生成 ZIP，在源码/CI 中 `install` 后接入本地 Composer path、迁移和菜单节点同步；移除前自动执行带数据备份。前端发生变化后仍需重新编译，不存在生产二进制热加载。

### 发布与恢复

发布安装包固定包含 MySQL、SQLite 双结构、共享必要数据和校验元数据。生产首次安装或升级通过 `restore --install` 恢复，并执行受控数据修复和前端发布；普通运行备份默认不包含全量业务数据。

## 安全边界

- 缺少有效租户或用户上下文时，标准业务查询和操作应拒绝或返回空集。
- 外部请求不能控制 select、order、raw SQL、关联名、租户或未注册表达式。
- 插件 ZIP 防止路径穿越，自有表只来自清单声明的表或前缀。
- Builder、Library、System 等基础模块不能被普通插件管理命令覆盖或移除。
- `xadmin:plugin:*`、构建和文档检查属于源码期命令，不进入 Phar/SFX。
- `--install` 采集只能在构建器受控 staging 使用，发布安装包禁止携带全量生产数据。
- 恢复遇到破坏性结构变化默认拒绝，只有明确授权后才能强制执行。

## 合理推测

- 业务插件将继续复用 Library，而不是分别实现租户、数据范围和响应框架。
- OpenAPI 共用工具会服务更多业务开放接口，但 Library 自身不会拥有业务端点。
- 发布安装包、运行备份和插件备份会继续保持不同概念，避免交付物混入生产全量数据。

## 当前不应宣传为已实现

- 生产运行时远程插件市场或热安装。
- Library 自己拥有业务菜单、业务角色或业务数据。
- 默认备份包含全部业务数据，或生产升级逐条依赖迁移文件。
