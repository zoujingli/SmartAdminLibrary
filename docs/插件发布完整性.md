# 插件发布完整性

本文是可安装插件从开发源到 Release ZIP 的标准。触发范围包括插件 `composer.json`、Provider、`plugin.json`、声明资源目录、迁移、`xadmin:plugin:*`、`.github/tools/release/package-plugins.sh`、插件资产清单和分发属性。

## 完整产物定义

插件发布完整性分为四层，任一层失败都不能把 ZIP 视为可交付插件。

### 源码完整

- `composer.json` 与 `plugin.json` 必须存在、可严格解析，Composer 包名遵循 `zoujingli/smart-plugin-xxx`。
- `plugin.json` 与 Composer 同时声明版本时必须一致；菜单、权限、入口和分发属性以清单为准。
- Composer autoload、Provider 和插件运行代码必须闭合；不得依赖 Developer 仓中未随插件或公开基础包交付的私有源码。
- `view_root`、`language_root`、`migration_root` 只在明确声明时生效；声明后的目录、菜单 view、语言包和迁移文件必须随源码存在。
- `tables`、`table_prefixes` 或由 `plugin.code` 推导的前缀必须覆盖插件自有表，避免备份、恢复或移除遗漏数据。

### ZIP 完整

- 只使用 `xadmin:plugin:package` 生成插件 ZIP，复用 `PluginMetadata` 与 `PluginArchive`；不另写复制或压缩脚本。
- ZIP 至少保留元数据、Provider/运行源码和已声明资源；`.git`、IDE 配置、`vendor`、`node_modules`、`runtime`、嵌套 ZIP 等开发或缓存材料不得进入。
- 私有、会员和定制插件在真实交付时必须加密；本地允许无加密只用于显式测试，不得把测试包上传到 Release。
- 安装、覆盖和恢复只在源码/CI 环境执行；发布 Phar/SFX 不注册 `xadmin:plugin:*`，插件前端变化后必须重新构建 Web 产物。

### Release 资产完整

- TAG Release 统一通过 `.github/tools/release/package-plugins.sh` 扫描所有带 `plugin.json` 的可安装插件，资产名固定为 `plugin-<code>-<tag>.zip`。
- `plugins-manifest.json` 必须为每个 ZIP 记录 code、版本、包名、授权类型、文件名、大小和 SHA-256；ZIP 缺失时清单生成必须失败。
- 开源资产和私有资产依据清单分流；公开 Release 只上传开源 ZIP 与对应清单，Developer 私有 Release 才能上传完整插件集合。
- ZIP 名称使用发布 Tag，插件内部版本继续来自 `plugin.json`/Composer；两者语义分别是“本次 Release 批次”和“插件自身版本”，不能相互覆盖。

### 安装边界完整

- 安装后必须维护根 Composer path repository/require，并按参数执行迁移、菜单同步和节点同步。
- 覆盖安装必须显式 `--force`；移除前自动执行带数据备份，基础插件不允许通过普通插件命令覆盖或移除。
- 插件包不承担生产数据库升级；正式 Phar/SFX 仍通过 release v2 双 schema 安装包恢复。
- 安装和恢复必须先在独立 Composer 清单/锁文件中用解压区候选包执行 `update --dry-run --no-scripts --no-plugins`；不能先覆盖旧目录，再依靠依赖解析失败阻止不兼容升级。预检不执行迁移、同步或依赖安装，临时清单/锁文件在结束时删除。
- 预检通过后，代码事务保存目标插件、根 `composer.json` / `composer.lock`、vendor 和独立 bin-dir 的回滚副本；代码复制或 Composer 更新失败时恢复这些状态，包括不存在的旧锁文件、path 软链和文件权限。回滚失败必须保留受限权限的恢复材料并报告位置，不得假报成功或删除唯一恢复副本。
- 同一项目的代码/Composer 变更使用项目级互斥锁，移除也遵守该锁。vendor/bin-dir 仅允许项目内受控且不重叠的路径；目标目录及父目录不能是软链，vendor 内的 path 软链只复制链接文本、不跟随到外部源码。
- 事务只覆盖代码与 Composer 状态；Composer 成功后才执行迁移、数据恢复、菜单/节点同步，这些数据库操作以及自定义 Composer 脚本的外部副作用不承诺自动回滚。操作应安排维护窗口，预留至少能容纳待替换插件与当前 vendor 的额外磁盘空间，不将源码期命令当作在线零停机发布。

## 最小变更流程

1. **定位拥有方**：优先在目标插件内复用现有分层、Provider、清单和前端入口；完成标准是公共壳层没有新增该业务插件的私有引用。
2. **核对声明**：只更新本次变化涉及的 Composer、Provider、菜单权限、资源根、表归属和分发字段；完成标准是声明与真实文件、路由、权限和表结构一致。
3. **验证源码**：先运行目标插件最近的语法、单元、合同或前端测试；完成标准是改动行为有直接覆盖且无无关全量测试代替。
4. **验证 ZIP**：生成单插件 ZIP，确认 Provider/运行源码和声明资源存在，开发缓存不存在；完成标准是包可被 `PluginMetadata` 读取并由 `PluginArchive` 安全解压。
5. **验证发布链**：只有命中公共导出、分发属性、插件打包脚本或 Release workflow 时才扩大到完整清单和目标仓；完成标准是清单哈希、开源/私有分流及目标仓验证全部通过。

## 实际影响面验证矩阵

| 改动范围 | 最小验证 | 需要扩大验证的条件 |
| --- | --- | --- |
| 仅插件后端业务 | 修改文件语法检查 + 最近的插件单元/合同测试 | 触及共享 Library、数据库发布或跨插件接口时扩大到对应模块/导出仓 |
| 插件前端页面或路由 | 最近的前端测试/类型检查；确认 `plugin.json` view 仍指向真实文件 | 触及 `routes.ts`、`auth-entry.ts`、共享组件或发布产物时运行 `composer web:build` |
| 插件 Composer、Provider、`plugin.json`、资源根 | `(cd plugin/<Module> && composer validate --strict)`、严格解析 `plugin.json`、`PluginManifestRegistryTest`、单插件 package | 触及公开/会员属性时增加 `PublicExportContractTest` 与 SmartAdmin 导出 |
| 插件表、迁移或数据归属 | 最近的数据库/Service 测试、核对 `tables/table_prefixes`、带数据备份 dry-run | 进入 release 安装包或数据修复时增加 `composer release:check` 相关链路 |
| Library 插件管理/ZIP | `PluginManagerTest`，包括真实 Composer 下的安装/恢复兼容门禁，以及预检/部分安装失败后的代码、锁文件、vendor 可用性 | 修改导出测试或公共包时完整执行 Library 导出、包内 PHPUnit 与 PHPStan |
| `package-plugins.sh`、清单生成或 Release workflow | `PublicExportContractTest::testPluginReleaseWorkflowPreservesCompleteVerifiableAssets`，在隔离输出目录运行完整插件打包脚本 | TAG/Release 变更再核对 Developer 与公开 Release 上传步骤 |
| 仅本文或 AGENTS 规则 | `composer docs:check`、`git diff --check` | 文件会进入 Library/SmartAdmin 导出时增加对应导出解析和文档检查 |

## 标准命令

```bash
# 单插件元数据与 ZIP
(cd plugin/<Module> && composer validate --strict)
./bin/swoole-macos-a64 vendor/bin/phpunit tests/Unit/Library/PluginManagerTest.php
./bin/smart.php xadmin:plugin:package <Module> --json

# 清单与公开分流相关改动
./bin/swoole-macos-a64 vendor/bin/phpunit tests/Unit/Release/PublicExportContractTest.php \
  --filter testPluginReleaseWorkflowPreservesCompleteVerifiableAssets

# Library 插件管理链导出
.github/tools/release/export-library.sh "$PWD" <临时目录>/SmartAdminLibrary <tag>
```

完整 Release 插件打包必须使用隔离输出目录和安全环境变量提供的商用 ZIP 密码；不得把密码写入命令历史、仓库、日志或清单。
